Custom operators (macros)

One-argument templates over x, e.g. exp(-square(x)), expanded into the expression as the search builds it. x must appear exactly once (so sin(x)/x is not expressible), and numbers in a body become tunable constants seeded at that value — x^3 is a fitted power, not a cube. Complexity counts the expanded nodes and results print the primitive form. A body may use operators that are not checked above. Off by default — with no macros the search is unchanged.

Large data

Batching evaluates each iteration on a random batch_size rows instead of the whole table, making a candidate evaluation cost O(batch_size) rather than O(rows). The hall of fame, the early-stop test and the reported result are always recomputed on the full data, so a returned model's loss still means what it says. Measured here: about 18× faster at 10,000 rows and 22× at 100,000. It does not reduce memory — every row still lives in the WASM heap — so it is a cure for slow runs, not for the row limit.
